# 排练分谱排页

给乐手的排练分谱排页工具。输入每个小节的谱面行数、每页能排几行，以及实际演奏顺序
（最多 48 步，可在任意两步之间标记空拍），程序给出**页数最少**的分页方案，并逐步列出
每一步应该看第几页、用的是本页正文还是页首重印本。

排过一次后可以锁定已印的前几页，改动演奏顺序再排；锁定的页面原样保留。若排不出，
页面会明确提示无解，并指出上次的排法已不可用。

## 运行

```bash
docker compose up --build
```

打开 <http://localhost:8000>。

也可以不用 Docker 直接跑：

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
SECRET_KEY=dev python -m flask --app app run --port 8000
```

## 排页规则

1. 小节按谱面顺序接排：每页是一段**连续**的小节，每节整节印在一页上，不拆节。
2. 每页最多排 `每页行数` 行新内容。
3. 第 2 页起可以在页首**重印上一页的末节**，重印的部分同样占用行数，使该节在下一页
   也有一份印本。
4. 演奏从第 1 页开始：第 1 步所在的页必须是第 1 页（通常也就是以第 1 小节起奏）。
5. 相邻两步之间，只有勾选了空拍才可以**向前或向后翻一页**；没有空拍的两步必须在同一页。
6. 反复演奏时，同一个小节的每一步都可以任选一份印本：本页正文，或下一页页首的重印。
7. 优化目标依次为：页数最少 → 页首重印最少 → 页断更靠前。

## 锁定与无解

- 每次成功排页后，结果会记在当前浏览器会话里。锁定前 N 页后再排时，这 N 页原样保留，
  只重排后面的小节；第 1 个未锁页也可以重印锁定末页的末节。
- 如果锁定页在新设置下已经超出行数、剩余小节排不进去，或演奏顺序无法逐页完成，
  结果判为**无解**。若上次排法仍存在，会一并标出「上次排法不可用」并附上旧排法供核对。

## 实现要点

- `solver.py`：纯逻辑，不依赖 Flask。分页候选按「小节连续切块」枚举（≤ 12 节，至多
  2^11 种）。可排性用页位掩码可达性判断：状态是（第几步，当前页），只有空拍处允许 ±1 页，
  且该页必须印有当前小节。
- 重印只会**增加**同一节的可用印本，不会让原本可行的页数变不可行，所以第一阶段仍用
  「所有放得下的重印都打开」的最大排版筛出最少页数候选。
- **固定分页后一次性求最少重印**（`select_reprint_pages`，本次提速点）：每节只有一个正文页
  和至多一个额外印本（下一页页首重印），所以某一步能站的页只能是该节正文页或再后一页，
  重印只会把可选页向高页码扩一格。据此做一次反向可达掩码扫描，再从第 1 页起逐格取
  「仍能走完后缀的最低页」。这条最低路线压到的重印，是**任何**可行走法都必须压到的，因此
  收集到的页号集合就是唯一的最小重印集；同一处页首重印被多个反复步用到时，页号在集合里只
  出现一次。单分页挑选开销为
  `O(小节数 + 页数 + 演奏步数)`（实测计数循环约 `2(S+P+T)-1` 个线性单元），不再为同一种分页
  按子集反复试算 `itertools.combinations` 并重复 `perform`。
- 锁定页（含其页首重印）始终原样保留：重印照常占行、照常进入印本掩码可供演奏，即使新演奏
  顺序一次也用不到也不会被剥除；重印总数与行数字段都把它计入。锁定全部页时直接校验并演奏
  这一份固定排版（旧实现在「全锁页且需要锁定重印」时会触发断言，已修）。
- 全局排序仍是 `(页数, 重印总数, 页断签名)` 取最小：页数最少 → 重印（含锁定重印）最少 →
  页断更靠前。定稿后调用 `perform` 反解出逐步页码与「本页正文／页首重印」印本标注。
- `app.py`：Flask 表单处理 + 会话内的上次结果；锁定页从会话里的上次结果取前 N 页。
- `templates/index.html`：单页界面，可增删小节/步骤，勾选空拍，锁定页数；结果含分页表、
  逐步页码表和打印样式。
- `test_solver.py`：单元测试 + 与独立的穷举参考实现对拍（含锁页、锁定重印、全锁页场景），
  线性选择器对拍固定分页的子集穷举、复杂度计数断言、「求解过程不调用
  `itertools.combinations`」的守护测试，以及 HTTP 流程测试。

## 自测

```bash
python3 -m pytest -q
```

本次改动后 `40 passed`。另做了以下离线核对（脚本在仓库外的临时目录，不进镜像）：

- 5000 余个随机真实案例与独立穷举参考对拍（含锁页、刻意制造的锁定页重印、紧容量跨页反复），
  页数／重印数／精确排版全部一致，零分歧；仓库自带的参数化对拍测试另含数百例。
- 线性选择器在 40 万随机抽象实例 + 61 万个小规模全枚举实例上，与子集穷举最优一致，并满足
  「最低路线收集集是每个可行选择的子集（唯一最小集）」这一强性质。
- 开销核实：12 页、11 个重印位且必须全部启用的同一分页，旧子集法要试算 `2048` 个子集
  （约 53 ms／分页，试算量随页数 `2^(n-1)` 增长），新选择器一次线性扫描、工作量单元
  `2(S+P+T)-1 = 93`（同机约几十微秒量级），工作量随小节/页/步之和线性增长。
- 用 Flask 测试客户端和真实 HTTP（cookie 会话）走了：跨页往返反复
  `1,2,3,4,3,2,1` → 页码 `1,1,2,2,2,1,1`；同一页首重印被反复使用只计 1 处；锁定含重印的
  第 2 页后用不到该重印，页面仍显示「页首重印第 2 小节 / 锁定保留」且占行不变；锁第 1 页排入
  无解顺序时显示「无解」并标出「上次排法不可用」。
- 用与镜像相同的 `gunicorn --workers 2 --threads 2 app:app` 本地起服，`/healthz` 与 `/solve`
  均正常；`docker-compose.yml` 通过 YAML 解析。当前沙箱没有 Docker CLI/守护进程，因此没能在
  这里实际执行 `docker compose up --build`，这一项需在有 Docker 的环境最后确认。

## 未完成项

- 本次只把**固定分页后挑选重印**改成了线性 `O(S+P+T)`；外层「连续切块」仍枚举至多
  `2^11` 种分页（小节数上限 12 时足够快），没有把整题改成多项式/线性。
- 当前开发沙箱没有 Docker CLI/守护进程，未能实跑 `docker compose up --build`；已用镜像同款
  gunicorn 命令本地验证启动与 `/healthz`、`/solve`，并校验了 compose YAML，仍建议在有 Docker
  的机器上做一次最终构建启动确认。
- 会话存在浏览器签名 Cookie 中，换浏览器/清 Cookie 后「上次排法」与锁页信息会丢失；
  没有做服务端持久化。
- 只支持整节不拆页；没有实现跨页拆节或页内再折行。
- 「重印上一页末节」只允许一节，没有做多节重印或任意页面重印。
- 翻页规则限定为相邻页 ±1，没有支持一次翻多页（例如双页展开）。
